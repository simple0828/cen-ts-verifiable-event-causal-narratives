```text
Event-Target Lagged Causal Association Graph
```

[

```text

```

主实验使用一种固定表示，其他表示作为补充实验。


所有数值检验只能使用 `train_core`。

至少实现：

### A. Distributed lag regression

比较：

```text
仅使用目标自身历史
vs

```

记录：

```text
增量解释能力
```

对事件强度序列与目标序列进行滞后预测增益检验。

```text

目标历史水平
```


### D. 时间置换检验

在训练区间打乱事件时间戳，检验真实对齐是否明显优于随机对齐。


# 十、模块四：滞后感知双向 verifier

verifier 不是简单让一个 LLM回答“可信/不可信”。

它由三部分构成。

## 10.1 文本证据分数

计算：

[
s_{\text{evidence}}
]

检查：

```text
事件是否有明确 evidence span
事件是否为已发生事实
event_time 是否合理
actor/action/object 是否受文本支持
多个来源是否一致
是否存在预测、意见冒充事实
```

## 10.2 因果相关分数

查询训练期因果关联图：

[
s_{\text{causal}}
]

检查：

```text
事件类型是否存在到目标的已接受边
影响方向
lag 区间
事件支持数
边稳定性
当前预测区间是否与预计影响区间重叠
```

预测区间：

[
[t+1,t+H]
]

事件影响区间：

[
[t_e+\ell_{\min},t_e+\ell_{\max}+d]
]

只有两者相交，事件才对当前样本具有预测相关性。

## 10.3 双向循环一致性分数

比较：

```text
文本抽取事件
vs
历史时间序列反推事件
```

计算：

[
s_{\text{cycle}}
]

至少比较：

```text
event type
direction
intensity
pattern type
time compatibility
```

## 10.4 滞后可观察 mask

事件刚发生时，其影响可能还没出现在历史序列中。

定义：

[
m_{\text{observable}}
=====================

\mathbb{I}
[t_e+\ell_{\min}\le t]
]

当：

```text
m_observable = 0
```

不得因为反向事件与文本事件不一致而删除该事件。

最终分数：

[
s_{\text{verify}}
=================

\lambda_1s_{\text{evidence}}
+
\lambda_2s_{\text{causal}}
+
m_{\text{observable}}
\lambda_3s_{\text{cycle}}
+
m_{\text{observable}}
\lambda_4s_{\text{lag-fit}}
]

权重和 threshold 只能通过 `model_val` 选择。

## 10.5 verifier 输出

```json
{
  "event_id": "...",
  "verified": true,
  "verification_score": 0.84,
  "evidence_score": 0.91,
  "causal_relevance": 0.86,
  "cycle_consistency": 0.72,
  "lag_fit": 0.78,
  "observable": true,
  "corrected_direction": "positive",
  "corrected_lag_min": 1,
  "corrected_lag_max": 7,
  "effect_status": "not_started|partially_observed|observed",
  "decision_reason": [],
  "supporting_graph_edge": "edge id"
}
```

```text
Estimated lag
Expected duration
Textual evidence
Numerical consistency
Verification confidence
```

示例：

```text
A supply-reduction event occurred on 2022-03-01.
This event type has a positive historical association with the target.
The estimated effect window is 1 to 7 time steps after the event.
The claim is supported by two independent text sources.
The historical numerical pattern is partially consistent with the event.
Verification confidence: 0.84.
```

## 11.2 不允许叙事添加新事实

叙事只能使用 verifier JSON 中已有字段。

增加自动检查：

```text
实体必须来自事件 JSON
数字必须来自事件或图边 JSON
方向必须来自 verifier
lag 必须来自 verifier
不得添加未知原因和新来源
```

## 11.3 多事件处理

同一时间点存在多个事件时：

```text
按 verification_score 排序
最多保留 K 条
使用固定分隔符
保持最大 token 长度一致
```

主实验使用 deterministic top-K。

K 只能通过 model_val 选择。

不要新增可学习事件聚合网络。

# 十三、APO 在本论文中的正式实现

APO 是离线提示程序优化器，不是 forecasting 模块。

需要优化四个提示：

```text
P_extract
P_inverse
P_verify
P_narrative
```

保存到：

```text
prompts/v5/manual/
prompts/v5/apo/
```

## 13.1 APO 优化数据

只使用：

```text
train_core
prompt_dev
```

不允许使用：

```text
model_val
test
```

其中：

```text
prompt_dev 用于比较候选 prompt
model_val 用于最终模型、threshold 和 hyperparameter 选择
```

## 13.2 APO 单轮流程

对于当前 prompt (P_r)：

1. 在 prompt_dev 抽取一批失败样本；
2. 收集模块运行轨迹；
3. 生成 textual gradient；
4. 根据 gradient 改写 prompt；
5. 生成多个候选；
6. 评估候选；
7. beam search 保留前 B 个；
8. 重复多轮；
9. 冻结最优 prompt。

## 13.3 textual gradient 输入

至少包括：

```text
原始输入
当前 prompt
当前输出
schema 错误
证据错误
事件时间错误
方向错误
因果图冲突
循环一致性错误
被 verifier 错误删除的事件
被 verifier 错误保留的事件
下游 validation 预测错误摘要
```

textual gradient 输出示例：

```text
当前提示经常将预测性陈述误认为已发生事件；
没有区分报道时间和事件时间；
在事件影响尚未进入可观察 lag 时，
过度使用序列不一致性否定事件；
叙事中加入了 verifier JSON 不包含的因果解释。
```

## 13.4 候选评价采用两阶段机制

为了避免每个 prompt 都完整训练模型：

### 阶段 A：低成本筛选

使用 prompt_dev 子集，评价：

```text
JSON schema validity
evidence-span groundedness
event-time accuracy
factuality classification
target relevance
cycle consistency
causal graph consistency
narrative faithfulness
token cost
```

保留前若干候选。

### 阶段 B：预测评价

对阶段 A 的 top candidates：

```text
生成完整 prompt_dev 辅助文本
通过同一个 TaTS encoder
使用相同训练预算训练小规模模型
评价 prompt_dev forecasting metric
```

再选择 top candidates 进入完整训练。

最终最优 prompt 冻结后：

```text
重新生成 train_core / model_val / test 输入
完整训练 TaTS
只在最终阶段评价 test
```

## 13.5 APO 目标

使用归一化后的综合目标：

[
J(P)
====

w_fL_{\text{forecast}}
+
w_eL_{\text{event}}
+
w_cL_{\text{cycle}}
+
w_gL_{\text{grounding}}
+
w_sL_{\text{schema}}
+
w_tL_{\text{token}}
]

其中：

```text
forecast：prompt_dev 预测误差
event：事件字段错误
cycle：文本事件和数值事件不一致
grounding：证据或叙事幻觉
schema：格式错误
token：API 和 token 成本
```

所有权重和 beam 参数写入配置，不得硬编码。

建议初始搜索：

```yaml
apo:
  beam_width: 3
  candidates_per_parent: 3
  max_depth: 3
  minibatch_size: 16
  stage_a_top_k: 5
  stage_b_top_k: 2
```

资源不足时可以缩小，但必须记录。

# 十五、必要消融和控制实验

至少运行：

## A1：Zero-text TaTS

保留相同文本通道维数，但全部置零。

用于排除输入维度变化造成的影响。

## A2：Shuffled raw text

在训练区间内打乱文本时间戳。

## A3：Shuffled event time

打乱事件时间戳但保留事件数量和类型分布。

## A4：Random causal graph

随机重连事件类型与目标，同时匹配真实图边数量和 lag 分布。

## A5：Causal graph without numerical tests

只使用 teacher LLM 建议，不运行数值检验。

用于证明数值验证是否必要。

## A6：Verifier without inverse event

去掉 `s_cycle`，保留证据和因果图。

## A7：Verifier without lag-aware mask

始终使用序列一致性评分。

用于证明 lag-aware mask 是否避免误删新事件。

## A8：Random verifier

随机保留与真实 verifier 相同数量的事件。

用于排除“仅仅减少文本量”带来的正则化效应。

## A9：Shuffled inverse event

打乱数值反推事件描述。

## A10：APO without forecast feedback

APO 只使用事件质量和一致性，不使用下游预测误差。

## A11：APO without event feedback

APO 只使用预测误差，不使用事件质量反馈。

## A12：Manual prompt vs APO prompt

使用完全相同的模型和数据，比较人工 prompt 与 APO prompt。
